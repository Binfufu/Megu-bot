# 17 · 通道策略表 —— 每条通道:满了怎么办 / 迟了怎么办

> ⚠️ **本页由 `src\channel-policy.js` 的数据渲染生成,别手改**(数据只此一份;
> 改数据 → 重新生成 → 页与数据不同步时,维护侧的检查会变红)。
>
> **用途**:任何一条"塞不下 / 来不及"的现场(被截断、过期、没轮到),先在表里找到那条通道,
> 对"满了/迟了"两列 —— **对不上就是 bug,对得上就是设计**。
> 来源:跨游戏模组调研第 3.1 节 —— 每条通道都要有"溢出"与"过期"的成文对策。

| 通道 | 满了怎么办 | 迟了怎么办 |
|---|---|---|
| 被动回复(有人跟她说话 → 她答话) | 平台:**一条入站消息最多 5 条**被动回复(`MAX_PASSIVE_SEQ`)。答话与主动**同一份**分条规划(`planSpokenLines`,1.171.0 / D288),超量的段**并进最后一段** —— 不截断、不转主动配额 | 这一轮超过回复超时就不说(日志 `这一轮超时（她没说话）`),**不补发** |
| 她自己开口(自发发言 / 事件钩子收尾 / 暖群) | 按**情绪上限分条发**(`splitSpokenLines`,段数上限借用 5,多的并进最后一段);**配额闸门**:距上次主动开口不足 `gapMs`(**默认 45 分钟**)就不开口 | 错过这一拍就等下一拍(调度到点再看),**不补发**;平台主动消息另有 20/分钟、1000/天 |
| 位置 / 在场("她在哪") | 一条事实,不排队 —— 新位置覆盖旧位置 | TTL 到期即"不在这儿了";TTL 是**派生**的:`whereaboutsTtlMs()` = 基础 30 分钟,`life` 那一档 **+ 一个 life 周期** |
| 到达报备("她到了") | 一条消息,不分条 | 新鲜窗口 = `arrivalFreshnessMs()` = **max(30 分钟, 两次之间的间隔)**;窗口外不报"到了" |
| 记忆交接(她醒来时看到的那一段) | 总预算 `HANDOFF_BUDGET` = **1400 字**(最近几轮原文 + 摘要各占一份);超了就按预算裁 | 交接**只读已经缓存好的**摘要 —— 摘要慢了这一代就用旧的,绝不阻塞对话 |
| 滚动摘要(后台那条) | 目标 400 字(`QQBOT_MEMORY_SUMMARY_CHARS`),交接里给它 480 字 | **最小间隔 3 小时**(`SUMMARY_MIN_INTERVAL_MS`)+ 攒够 **12 轮**(`SUMMARY_REFRESH_TURNS`)才重算;⚠️ 它挂在**每 15 分钟补归档**那一拍上 → "3 小时到了"最多还要再等十几分钟(**判据看日志,不看时间**) |
| 连发合并(他一口气发好几条) | 攒在窗口里**一起**处理(`pending`),条目数与窗口由 `burst-queue.js` 管 | **每来一条窗口重新计时**;那个会话正在跑就延迟再看(`isBusy`) |
| 出站留痕 / 指标(可删的**观测**) | 不排队:每一条真的发出去的消息各写一行 | 保留 **30 天**,与指标同一档;到期由那一拍 `pruneOutbound` 删 |

## 逐条:最容易出事的那个坑 + 凭什么这么写(锚)

### 被动回复(有人跟她说话 → 她答话)
- ⚠️ 1.171.0 / D288 起**答话也分条**:「说一半」那笔账是**截断**欠的(D171),分段一个字不丢; `msg_seq` 由 `sendSpokenLines` 接续数(1..5)。总开关/回滚口 = `QQBOT_SPOKEN_SPLIT`
- 锚:`src/index.js` 有 `const MAX_PASSIVE_SEQ = 5;`
- 锚:`src/index.js` 有 `这一轮超时（她没说话）`

### 她自己开口(自发发言 / 事件钩子收尾 / 暖群)
- ⚠️ 行尾标点在**分条之后**去掉(分条时还留着,好让切句按标点走)
- 锚:`src/selfcare.js` 有 `gapMs: 45 * 60_000,`
- 锚:`src/mood.js` 有 `export function splitSpokenLines`
- 锚:`src/config.js` 有 `20/qpm`

### 位置 / 在场("她在哪")
- ⚠️ 死链就出在这儿:TTL 30 分钟 < 两次 life 之间 3 小时 → **`她自己出门` 线上 0 次**(1.106.0 查出)
- 锚:`src/selfcare.js` 有 `export function whereaboutsTtlMs`

### 到达报备("她到了")
- ⚠️ 窗口要比配额闸门(`gapMs` 45 分钟)**长**,否则永远轮不到她报备(同一条死链的另一半)
- 锚:`src/selfcare.js` 有 `export function arrivalFreshnessMs`

### 记忆交接(她醒来时看到的那一段)
- ⚠️ 摘要是"冻结"的:它不在这条路上现算(现算会死锁,见 D135)
- 锚:`src/memory-archive.js` 有 `export const HANDOFF_BUDGET = 1400;`
- 锚:`src/memory-archive.js` 有 `export function buildHandoffWithSummary`

### 滚动摘要(后台那条)
- ⚠️ "攒够 N 轮"那条判据实测**恒为真** —— 真正挡着的是最小间隔(D135 那次烧钱的教训)
- 锚:`src/memory-store.js` 有 `export const SUMMARY_MIN_INTERVAL_MS = 3 * 3600 * 1000;`
- 锚:`src/memory-archive.js` 有 `export const SUMMARY_REFRESH_TURNS = 12;`
- 锚:`src/config.js` 有 `QQBOT_MEMORY_SUMMARY_CHARS`

### 连发合并(他一口气发好几条)
- ⚠️ 合并之后"她这一轮"看到的是**几条第** —— 复盘时别把合并后的当成他一次说完的
- 锚:`src/burst-queue.js` 有 `窗口重新计时`
- 锚:`src/burst-queue.js` 有 `isBusy`

### 出站留痕 / 指标(可删的**观测**)
- ⚠️ `memory.db` 的轮次**不可再生**(源文件会被保留策略删),所以两者保留口径**故意不同**
- 锚:`src/sqlite-store.js` 有 `pruneOutbound(`
- 锚:`src/index.js` 有 `outbound`

## 怎么用这一页(判据)

抽一条**现有日志**,逐句对上表;对不上的地方就是下一个要修的口径。三个现成例子:

- `事件钩子收尾(aqua_church)：按短句分 4 条发（88 字 → 22+23+21+20，每段上限 30）` → 通道「她自己开口」:
  4 条 ≤ 5(平台/段数上限)、每段 ≤ 30 字(情绪上限)—— ✅ 对得上。
- `滚动摘要：… 重算完 451 字（覆盖 88 轮）—— 攒了 20 轮新记录,且距上次已 188 分钟` → 通道「滚动摘要」:
  20 ≥ 12(轮次门槛)、188 ≥ 180 分钟(最小间隔)—— ✅ 对得上(多出来的 8 分钟正是"挂在 15 分钟归档拍上")。
- `她自己出门` / `她走到了` **线上 0 次** → 通道「位置 / 在场」+「到达报备」:
  TTL 30 分钟 < 两次 life 间隔 3 小时 —— ❌ **对不上**(1.106.0 已改成派生口径,⏳ 还没等到实证)。

## 这一页**不**管什么

- 不写"发什么内容"(那是提示词与本地角色内容的事);它只写**容量与时间**这两条边界。
- 数字多数是**暂定**:`gapMs` 45 分钟、TTL 30 分钟、摘要 3 小时/12 轮/400 字 —— 改之前先看这里写没写"暂定"。
