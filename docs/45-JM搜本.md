# JM 搜本/下本（可选功能）

> 状态：可选、**默认关闭**。本文描述 Node 侧行为、边车 API 契约，以及随仓库提供的可选边车工具
> `tools/jm-sidecar/` 的部署方式（见第 2 节）。边车是独立的本地 Python 服务，不参与 bot 运行时，
> 也不被 Node 代码 import。

## 1. 这个功能做什么

在已授权的 QQ 群里 @ 机器人，发这两类指令，整条链路**不经过模型**：

| 指令 | 机器人做什么 |
|---|---|
| `搜本 <关键词>` / `找本 <关键词>`，可带数量 1..5（如 `搜本 全彩 3`） | 调本机 JM 边车搜索。**恰好 1 本（站点 total=1、没写数量、且这本只有 1 个单元）时**下载并打包成整本 PDF 发进群；**多本时只回文字清单**（序号 + JM 编号 + 作品标题）；0 本回固定话术。 |
| `搜本 <编号>` / `找本 <编号>`（纯数字，如 `搜本 1195659`） | **不走站内关键词搜索**，先按编号精确解析：解析成作品 → 只有 1 个单元就下载发 PDF、多个单元本就回**单元清单**问下哪一条；解析成单元（章节）→ 回所属作品的单元清单并标出「你要的是第 N 个」。解析不到回固定话术，**不拿搜索兜底**。 |
| `下本 <编号>`（如 `下本 1490076`）/ `下本 <单元编号>` | 按编号精确解析后下载：给的是单元编号就**只下这一单元**；给的是多单元作品编号就先回单元清单；单单元作品下整本。完成后把 PDF 作为群文件发出（`file_type=4`，通用文件名 `JM<编号>.pdf`）。**成功时不补文案，只有失败才回固定话术。** |
| `下本 <序号>`（如 `下本 3`） | 取本群**最近一次清单**：有单元清单先按单元清单，否则按上次多本搜索结果。序号 1..9；清单超过 9 条时用清单里的单元编号选。 |

- `下载本子 <编号>` 是 `下本` 的别名。
- 单元清单新增「整本打包（#全部单元）」与「打包1 3 5 7（#选择单元打包）」：发 `整本打包` 选本群最近单元清单的全部，发 `打包1 3 5 7` 只选第 1/3/5/7 个（可写空格、序号可超过 9），按清单顺序去重合并为**一个 PDF**。括号是说明，可不带；不会自动混入其它生肉/熟肉。无单元清单或任一序号越界时，下载前直接拒绝；任一下载失败都不发残缺选集。
- **编号（纯数字）永远走精确解析，不当关键词搜**：JM 站内搜索对某些编号会回无关作品（2026-11-12 现场：搜 `1205081` 出来 `1195659`），1.210.2 因此把错本当成单命中整本下载；1.210.3 起改为精确解析，解析结果和请求编号对不上就不下载。
- 公开命令表见 [命令与关键字](命令与关键字.md)（该页由 `node scripts/command-index.js --write` 生成，不要手改）。
- **不调模型**：命中指令后由代码检索/下载/发送；格式写歪了或服务不可用，也只回固定话术。

它**不做什么**：不自动爬取、不主动外发、不把内部路径或边车地址说给群友、不换群、不下载到本仓库的
`data/` 之外；也不会因为打开这个功能而改变搬图（`QQBOT_MEITU`）的行为。

## 2. 前置：JM 边车服务

bot 侧只包含 **Node 客户端**（纯解析 + 服务层 + 网络子进程 CLI）。真正的 JM 访问在部署者自己的
**JM 边车服务**里：它负责搜索、编号解析、下载、生成拼图/PDF 和网页阅读链接，本仓库的 Node 进程只按
下面的 HTTP 契约调用它。

随仓库提供了一份可选的边车实现：[`tools/jm-sidecar/`](../tools/jm-sidecar/README.md)
（Python 3.11+，需自行克隆两个上游 MIT 项目：JMComic-Crawler-Python、jm-view-server）。
最小部署步骤：

```bash
cd tools/jm-sidecar
git clone https://github.com/hect0x7/JMComic-Crawler-Python vendor/JMComic-Crawler-Python
git clone https://github.com/hect0x7/jm-view-server      vendor/jm-view-server
python -m venv .venv && .venv/bin/pip install -r requirements.txt
export PYTHONPATH="$PWD:$PWD/vendor/JMComic-Crawler-Python/src:$PWD/vendor/jm-view-server/src"
.venv/bin/python -m jm_service       # 默认监听 127.0.0.1:8790
```

也可以按下面的契约自行实现任意语言的边车；bot 只认契约、不认实现。

- 边车与本 bot 在**同一台机器**（或至少 `QQBOT_JM_API` 可达）；
- 边车默认监听 `http://127.0.0.1:8790`；端口不同就以 `QQBOT_JM_API` 为准（本仓库不硬编码端口）；
- 自检：`node scripts/jm-fetch-one.mjs --op health --api http://127.0.0.1:8790`，
  最后一行 JSON 里 `ok=true` 即通。

### 2.1 Node 客户端依赖的 API 契约（v3，向后兼容 v2/v1）

全部 JSON、UTF-8。错误统一 `{"ok": false, "error": "<机器可读码>", "message": "<中文一句>"}` + 适当 4xx/5xx。
路径里的图片地址既可以是绝对 URL，也可以是同 base 下的站内路径（`/preview/...`）。

| 方法/路径 | 用途 | Node 侧用到的字段 |
|---|---|---|
| `GET /health` | 健康检查 + 能力声明 | `ok`、`service`、`version`、`viewer_base`、`downloaded_albums`、`capabilities`（本版含 `"units"`） |
| `GET /search?q=<kw>&limit=<n>&page=1[&images=0]` | 按关键词搜索 | `ok`、`results[]`（`rank`、`id`、`title`、`authors`、`tags`、`page_count`、`cover_http`、`detail_ok`）、`text`、`total`、`cached`、`elapsed_ms`；`images=0` 时边车可跳过详情/封面/拼图 |
| `GET /resolve/<number>` | **按编号精确解析**（作品 id 或单元/章节 id） | `ok`、`kind`（`album`/`photo`）、`album`（含 `units`）、`matched_unit` |
| `GET /preview/<name>.jpg` / `GET /cover/<id>.jpg` | 搜索结果拼图 / 单本封面 | 图片二进制（Node 侧 1.210.2 起不再拉取） |
| `GET /album/<id>` | 作品详情（含单元清单） | `ok`、`album`（含 `units`、`unit_count`）、`viewer_url`、`downloaded`、`pdf_ready` |
| `POST /download` `{"id":"<作品id>","unit":"<单元id，可选>"}` | 请求下载整本或单单元；多单元作品未指定 unit 时回 409 `multiple_units` | `ok`、`status`（`done`/`queued`）、`job_id`、`unit`、`viewer_url`、`album.title` |
| `GET /jobs/<job_id>` | 轮询下载任务 | `ok`、`status`（`running`/`done`/`failed`）、`phase`、`unit_id`、`viewer_url`、`title`、`error` |
| `GET /pdf/<id>[?unit=<单元id>]` | 取整本 / 单单元 PDF（Node 侧发群文件用） | `application/pdf`；整本未下载 404 `album_not_downloaded`，单元未下载 404 `unit_not_downloaded` |
| `GET /pdf/<id>?units=<单元id,单元id,...>` | 合并已下载的所选单元，按系列清单顺序去重，不混入未选单元 | `application/pdf`；与 `unit` 互斥，非法或非本作品单元 400 `invalid_unit`；未全部下载 404；页数/体积超限 413；坏图 422，均不发残缺 PDF |

说明：

- **编号解析**：`/resolve/<number>` 先按作品 id 精确取详情；取不到再按单元（章节）id 找到所属作品，返回 `kind:"photo"` 和 `matched_unit`；两者都取不到回 404 `not_found`。**实现方不得拿站内搜索兜底**。
- **单元清单**：`album.units[]` 每项 `{index, unit_id, title, page_count}`（`index` 从 1 开始，`page_count` 可为 `null`）。
- **多单元作品**：`POST /download` 不带 `unit` 时返回 **409 `multiple_units`**（body 里带 `units`），**不创建下载任务**；这是为了不让「一个作品多个单元本」被当成一本整本打包（2026-11-12 现场 39MB / 超 120s）。
- `preview_url` / `cover_http` 仍在契约里（边车会给），但 **2026-11-12 起 Node 侧不再发拼图/封面**：
  多本只发文字清单，单本/单元直接发 PDF（QQ 图审实测会拦 `40034006`，且拼图对群友价值低）。
- `viewer_url` 仍由边车生成，但 Node 侧**不再发到群**（默认绑 `127.0.0.1`，群友设备打不开；
  只留在日志/本机使用）。
- 图片/PDF 的临时落盘都在 `QQBOT_JM_ROOT` 下的临时子目录，发送成功/失败后立即删除。
- 下载任务可能在边车侧排队（单 worker 串行），Node 侧按 `QQBOT_JM_TIMEOUT_MS` 预算轮询到
  `done`/`failed`。
- **PDF**：Node 客户端下载完成后调 `GET /pdf/<id>[?unit=]` 取 PDF，按 QQ 群文件（`file_type=4`，
  通用文件名 `JM<编号>.pdf`）发出；PDF 的页数/体积上限由边车配置（`pdf.max_pages` / `pdf.max_bytes`）。
- **合并打包的能力闸**：Node 在打包前先读 `/health.capabilities`，未声明 `units` 就回固定话术并停止（不下载任何单元）；这是为了不让旧边车把 `?units=` 静默当整本。
- **合并打包**：Node 先依次 `POST /download` 指定每个 `unit`，全部 `done` 后只调用一次 `?units=` 并只发一个选集文件（`JM<作品>-pack-<集合哈希>.pdf`）；多单元不指定 `unit` 的 409 保护不变。预算按每个单元操作计算，整体随单元数增长。
- **手机 PDF 格式**：标准 A4 页幅、图像保比例、超长图分页；压缩降级不改变页面物理尺度。版式/输入/配置签名变化后自动重建旧缓存；已经发出的旧文件不会自动变化，需重下。选集禁止因上限而静默截断，普通旧整本路径仍保留其页数截断兼容行为。

## 3. 配置

默认关闭；只编辑本地 `.env`，并保持 `QQBOT_ACCESS_MODE=allowlist`：

```dotenv
QQBOT_JM=true
QQBOT_JM_GROUPS=
QQBOT_JM_API=http://127.0.0.1:8790
QQBOT_JM_MAX=5
QQBOT_JM_COOLDOWN_MS=30000
QQBOT_JM_ROOT=data/demo/jm-images
QQBOT_JM_MAX_BYTES=10485760
QQBOT_JM_TIMEOUT_MS=120000
```

| 键 | 默认 | 含义 |
|---|---|---|
| `QQBOT_JM` | `false` | 总开关。没开时连指令解析都不进，启动也不联网。 |
| `QQBOT_JM_GROUPS` | 空 | 允许使用这个功能的群 openid 逗号分隔。**空名单 = 全部拒绝**（fail closed），不是全开；与 `QQBOT_IDS` 的用户授权相互独立。**要放行全部群必须显式写 `*`**（`QQBOT_JM_GROUPS=*`，或 `*,某群` 也当全部）—— 空值不会变成全开，这是有意的：避免"打开了却没配名单"静默变成对全群开放。 |
| `QQBOT_JM_API` | `http://127.0.0.1:8790` | 边车 base URL。端口以边车部署为准，可自行改。 |
| `QQBOT_JM_MAX` | `5` | 一页最多看几本（写多了夹到它）；不影响编号解析与单元清单。 |
| `QQBOT_JM_COOLDOWN_MS` | `30000` | 同群两次**搜本**的最小间隔。下本**不吃**冷却；失败不占冷却。 |
| `QQBOT_JM_ROOT` | `data/demo/jm-images` | 临时落盘根目录（PDF 等），发完即清。 |
| `QQBOT_JM_MAX_BYTES` | `10485760` | **兼容保留**：Node 侧 1.210.2 起不再发结果图，该值不再参与运行时判断。 |
| `QQBOT_JM_TIMEOUT_MS` | `120000` | 一次搜索/下载的一个操作预算，也是子进程硬超时的基准。 |

以上数字是【暂定】默认值；改 `.env` 即可，不用改代码。

## 4. 失败时的行为（都是固定话术，不调模型）

| 现场 | 群里会看到 |
|---|---|
| 群不在 `QQBOT_JM_GROUPS`（含空名单） | 「这个群没开 JM 搜本。」（且不会起子进程） |
| 边车没启动 / 连不上 / 回 4xx/5xx | 「JM 服务没启动，先启动 JM 边车服务。」 |
| 边车/抓取器超时 | 「JM 服务响应太慢，稍后再试。」 |
| 搜索失败（坏 JSON、边车报错等） | 「搜本没成功，稍后再试。」 |
| 搜到 0 本（含「total=0 但混进了推荐位」） | 「没搜到符合条件的本子。」 |
| 编号解析不到（不存在/不是作品或单元编号） | 「没有这个编号：JM 里找不到这本。」 |
| 一个作品有多个单元本 | 不发文件，回单元清单（序号 + `JM<单元编号>` + 单元标题），等用户选 |
| 下本失败 / PDF 没生成 | 「下载没完成，稍后再试或换一本。」 |
| `下本 <序号>` 但没有可用的清单 | 提示先搜本/先看清单，或直接发编号 |
| PDF 上传/发送失败（含平台内容审核 `40034006`、按天文件容量 `40093002`） | 「文件没发出去，稍后再试。」 |
| 其它兜底异常 | 「JM 处理出错了，稍后再试。」 |

## 5. 排障

1. **先测边车**：`node scripts/jm-fetch-one.mjs --op health --api http://127.0.0.1:8790`。
   - `service_down` → 边车没起或端口不对（核对 `QQBOT_JM_API`）。
   - `bad_json`/`http_error` → 边车实现了但契约不一致（对照第 2.1 节）。
2. **再测群白名单**：`QQBOT_JM_GROUPS` 为空是**拒绝所有群**；填的是群 openid（不是群号）；要放行全部群就写 `*`（显式，别留空）。
3. **编号对不上/搜出无关作品**：先手测 `node scripts/jm-fetch-one.mjs --op resolve --id <编号>`。
   - 返回 `kind:"album"`/`kind:"photo"` 且 `album.id` 就是你给的编号（或单元所属作品）→ 正常；
   - 404 → 编号不存在或不是作品/单元号，按「没有这个编号」收口；
   - 边车若把编号回退成站内关键词搜索，会重新出现「搜 A 出 B」——契约明确禁止（见 2.1）。
4. **下本没收到 PDF 文件**：先看边车日志里 `GET /pdf/<id>[?unit=]` 是否 200（带页数/大小），
   再看 bot 日志 `JM：PDF 没发出去`：`40034006` = 平台内容审核拦下、`40093002` = 当天文件容量上限；
   这两类换时间/降频处理，别连续重试。
5. **下本一直超时**：边车下载是单 worker 串行，排到队尾可能要等；调大 `QQBOT_JM_TIMEOUT_MS`，
   或先 `--op download --id <作品> --unit <单元>` 手动观察边车日志。多单元作品应先清单选单元，不要整本下。
6. **临时文件越积越多**：正常情况发完即删；进程被强杀时可能留下 `QQBOT_JM_ROOT/jm-*` 残留，可手工清理。

## 6. 边界与责任

- 这个功能默认关闭，且只有 `QQBOT_JM_GROUPS` 里明确列出的群能用；`*` 是显式的"全部群"，不留空就不响应。
- 部署者需要自行确认：JM/图片来源的使用条款、所在平台与地区对内容的要求、群成员的知情与授权。
  本仓库只提供通用 Node 客户端与契约，**不附带任何 JM 内容、图片、凭据或真实数据**。
- 机器人只把关键词与编号发给边车；搜索词、解析记录和下载记录会留在边车与 JM 侧，隐私边界由部署者自控。
- 公开自测只验证解析与编排契约（合成夹具、假网络/假子进程），不证明边车可部署、内容可用或平台条款允许；
  真实链路要在你自己的环境里验证。
