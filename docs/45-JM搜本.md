# JM 搜本/下本（可选功能）

> 状态：可选、**默认关闭**。本文描述 Node 侧行为、边车 API 契约，以及随仓库提供的可选边车工具
> `tools/jm-sidecar/` 的部署方式（见第 2 节）。边车是独立的本地 Python 服务，不参与 bot 运行时，
> 也不被 Node 代码 import。

## 1. 这个功能做什么

在已授权的 QQ 群里 @ 机器人，发这两类指令，整条链路**不经过模型**：

| 指令 | 机器人做什么 |
|---|---|
| `搜本 <关键词>` / `找本 <关键词>`，可带数量 1..5（如 `搜本 全彩 3`） | 调本机 JM 边车搜索。**结果恰好 1 本时立即下载并打包成整本 PDF 发进群**（搜本/下本合并）；**多本时只回文字清单**（序号 + JM 编号 + 作品标题），提示用「下本 <编号或序号>」；0 本回固定话术。 |
| `下本 <编号>`（如 `下本 1490076`）/ `下本 <序号>`（如 `下本 3`） | 按编号/序号下载；序号取**本群最近一次成功搜索**里的第 N 本。完成后把整本 PDF 作为群文件发出（`file_type=4`，通用文件名 `JM<id>.pdf`）。不再回网页阅读链接；**成功时不补文案，只有失败才回固定话术**。 |

- `下载本子 <编号>` 是 `下本` 的别名。
- 公开命令表见 [命令与关键字](命令与关键字.md)（该页由 `node scripts/command-index.js --write` 生成，不要手改）。
- **不调模型**：命中指令后由代码检索/下载/发送；格式写歪了或服务不可用，也只回固定话术。

它**不做什么**：不自动爬取、不主动外发、不把内部路径或边车地址说给群友、不换群、不下载到本仓库的
`data/` 之外；也不会因为打开这个功能而改变搬图（`QQBOT_MEITU`）的行为。

## 2. 前置：JM 边车服务

bot 侧只包含 **Node 客户端**（纯解析 + 服务层 + 网络子进程 CLI）。真正的 JM 访问在部署者自己的
**JM 边车服务**里：它负责搜索、下载、生成拼图/PDF 和网页阅读链接，本仓库的 Node 进程只按下面的
HTTP 契约调用它。

随仓库提供了一份可选的边车实现：[`tools/jm-sidecar/`](../tools/jm-sidecar/README.md)
（Python 3.11+，需自行克隆两个上游 MIT 项目：JMComic-Crawler-Python、jm-view-server）。
最小部署步骤：

```bash
cd tools/jm-sidecar
git clone https://github.com/hect0x7/JMComic-Crawler-Python vendor/JMComic-Crawler-Python
git clone https://github.com/hect0x7/jm-view-server      vendor/jm-view-server
python -m venv .venv && .venv/bin/pip install -r requirements.txt
export PYTHONPATH="$PWD:$PWD/vendor/JMComic-Crawler-Python/src:$PWD/vendor/jm-view-server/src"
.venv/bin/python -m jm_service       # 默认监听 127.0.0.1:8790
```

也可以按下面的契约自行实现任意语言的边车；bot 只认契约、不认实现。

- 边车与本 bot 在**同一台机器**（或至少 `QQBOT_JM_API` 可达、图片接口也走同一个 base）；
- 边车默认监听 `http://127.0.0.1:8790`；端口不同就以 `QQBOT_JM_API` 为准（本仓库不硬编码端口）；
- 自检：`node scripts/jm-fetch-one.mjs --op health --api http://127.0.0.1:8790`，
  最后一行 JSON 里 `ok=true` 即通。

### 2.1 Node 客户端依赖的 API 契约（v1）

全部 JSON、UTF-8。错误统一 `{"ok": false, "error": "<机器可读码>", "message": "<中文一句>"}` + 适当 4xx/5xx。
路径里的图片地址既可以是绝对 URL，也可以是同 base 下的站内路径（`/preview/...`）。

| 方法/路径 | 用途 | Node 侧用到的字段 |
|---|---|---|
| `GET /health` | 健康检查 | `ok`、`service`、`version`、`viewer_base`、`downloaded_albums` |
| `GET /search?q=<kw>&limit=<n>&page=1` | 按关键词搜索 | `ok`、`results[]`（`rank`、`id`、`title`、`authors`、`tags`、`page_count`、`cover_http`、`detail_ok`）、`preview_url`、`text`、`total`、`cached`、`elapsed_ms` |
| `GET /preview/<name>.jpg` | 搜索结果拼图 | 图片二进制（Node 侧下载后上传 QQ） |
| `GET /cover/<id>.jpg` | 单本封面（拼图不可用时的降级） | 图片二进制 |
| `POST /download` `{"id":"<id>"}` | 请求下载 | `ok`、`status`（`done`/`queued`）、`job_id`、`viewer_url`、`album.title` |
| `GET /jobs/<job_id>` | 轮询下载任务 | `ok`、`status`（`running`/`done`/`failed`）、`phase`、`viewer_url`、`title`、`error` |
| `GET /album/<id>` | 兜底取阅读链接 | `ok`、`viewer_url` |
| `GET /pdf/<id>` | 取整本 PDF（Node 侧「下本 / 单本搜本」用它发群文件） | `application/pdf`；未下载 404 `album_not_downloaded` |

说明：

- `preview_url` / `cover_http` 仍在契约里（边车会给），但 **2026-11-12 起 Node 侧不再发拼图/封面**：
  搜本多本只发文字清单，单本/下本直接发整本 PDF（QQ 图审实测会拦 `40034006`，且拼图对群友价值低）。
- `viewer_url` 仍由边车生成，但 Node 侧**不再发到群**（默认绑 `127.0.0.1`，群友设备打不开；
  只留在日志/本机使用）。
- 图片/PDF 的临时落盘都在 `QQBOT_JM_ROOT` 下的临时子目录，发送成功/失败后立即删除。
- 下载任务可能在边车侧排队（单 worker 串行），Node 侧按 `QQBOT_JM_TIMEOUT_MS` 预算轮询到
  `done`/`failed`。
- **整本 PDF**：Node 客户端在下载完成后调 `GET /pdf/<id>` 取 PDF，按 QQ 群文件（`file_type=4`，
  通用文件名 `JM<id>.pdf`）发出；PDF 的页数/体积上限由边车配置（`pdf.max_pages` / `pdf.max_bytes`）。

## 3. 配置

默认关闭；只编辑本地 `.env`，并保持 `QQBOT_ACCESS_MODE=allowlist`：

```dotenv
QQBOT_JM=true
QQBOT_JM_GROUPS=
QQBOT_JM_API=http://127.0.0.1:8790
QQBOT_JM_MAX=5
QQBOT_JM_COOLDOWN_MS=30000
QQBOT_JM_ROOT=data/demo/jm-images
QQBOT_JM_MAX_BYTES=10485760
QQBOT_JM_TIMEOUT_MS=120000
```

| 键 | 默认 | 含义 |
|---|---|---|
| `QQBOT_JM` | `false` | 总开关。没开时连指令解析都不进，启动也不联网。 |
| `QQBOT_JM_GROUPS` | 空 | 允许使用这个功能的群 openid 逗号分隔。**空名单 = 全部拒绝**（fail closed），不是全开；与 `QQBOT_IDS` 的用户授权相互独立。**要放行全部群必须显式写 `*`**（`QQBOT_JM_GROUPS=*`，或 `*,某群` 也当全部）—— 空值不会变成全开，这是有意的：避免"打开了却没配名单"静默变成对全群开放。 |
| `QQBOT_JM_API` | `http://127.0.0.1:8790` | 边车 base URL。端口以边车部署为准，可自行改。 |
| `QQBOT_JM_MAX` | `5` | 一次最多搜几本（写多了夹到它）。 |
| `QQBOT_JM_COOLDOWN_MS` | `30000` | 同群两次**搜本**的最小间隔。下本**不吃**冷却（否则「搜完立刻下」会被自己拦住）；失败不占冷却。 |
| `QQBOT_JM_ROOT` | `data/demo/jm-images` | 结果图（拼图/封面）的临时落盘根目录，发完即清。 |
| `QQBOT_JM_MAX_BYTES` | `10485760` | 单张结果图上限；超过的图不落盘/不发送（文本结果照发）。 |
| `QQBOT_JM_TIMEOUT_MS` | `120000` | 一次搜索/下载的总预算，也是子进程硬超时的基准。 |

以上数字是【暂定】默认值；改 `.env` 即可，不用改代码。

## 4. 失败时的行为（都是固定话术，不调模型）

| 现场 | 群里会看到 |
|---|---|
| 群不在 `QQBOT_JM_GROUPS`（含空名单） | 「这个群没开 JM 搜本。」（且不会起子进程） |
| 边车没启动 / 连不上 / 回 4xx/5xx | 「JM 服务没启动，先启动 JM 边车服务。」 |
| 边车/抓取器超时 | 「JM 服务响应太慢，稍后再试。」 |
| 搜索失败（坏 JSON、边车报错等） | 「搜本没成功，稍后再试。」 |
| 搜到 0 本 | 「没搜到符合条件的本子。」 |
| 下本失败 / 整本 PDF 没生成 | 「下载没完成，稍后再试或换一本。」 |
| `下本 <序号>` 但没有可用的上次搜索结果 | 提示先搜本，或直接发编号 |
| PDF 上传/发送失败（含平台内容审核 `40034006`、按天文件容量 `40093002`） | 「文件没发出去，稍后再试。」 |
| 其它兜底异常 | 「JM 处理出错了，稍后再试。」 |

## 5. 排障

1. **先测边车**：`node scripts/jm-fetch-one.mjs --op health --api http://127.0.0.1:8790`。
   - `service_down` → 边车没起或端口不对（核对 `QQBOT_JM_API`）。
   - `bad_json`/`http_error` → 边车实现了但契约不一致（对照第 2.1 节）。
2. **再测群白名单**：`QQBOT_JM_GROUPS` 为空是**拒绝所有群**；填的是群 openid（不是群号）；要放行全部群就写 `*`（显式，别留空）。
3. **下本没收到 PDF 文件**：先看边车日志里 `GET /pdf/<id>` 是否 200（带页数/大小），
   再看 bot 日志 `JM：PDF 没发出去`：`40034006` = 平台内容审核拦下、`40093002` = 当天文件容量上限；
   这两类换时间/降频处理，别连续重试。
4. **下本一直超时**：边车下载是单 worker 串行，排到队尾可能要等；调大 `QQBOT_JM_TIMEOUT_MS`，
   或先 `--op download` 手动观察边车日志。
5. **临时图片越积越多**：正常情况发完即删；进程被强杀时可能留下 `QQBOT_JM_ROOT/search-*` 残留，
   可手工清理（它们只是缓存）。

## 6. 边界与责任

- 这个功能默认关闭，且只有 `QQBOT_JM_GROUPS` 里明确列出的群能用；`*` 是显式的"全部群"，不留空就不响应。
- 部署者需要自行确认：JM/图片来源的使用条款、所在平台与地区对内容的要求、群成员的知情与授权。
  本仓库只提供通用 Node 客户端与契约，**不附带任何 JM 内容、图片、凭据或真实数据**。
- 机器人只把关键词与作品编号发给边车；搜索词和下载记录会留在边车与 JM 侧，隐私边界由部署者自控。
- 公开自测只验证解析与编排契约（合成夹具、假网络/假子进程），不证明边车可部署、内容可用或平台条款允许；
  真实链路要在你自己的环境里验证。

## 7. 相关代码与测试

| 文件 | 作用 |
|---|---|
| `src/jm-command.js` | 纯解析（搜本/找本/下本；数量 1..5；`parseJmCommand`、`looksLikeJmAttempt`），不联网、不读文件 |
| `src/jm-service.js` | 服务层：群白名单、按群串行、冷却、spawn 子进程、上传发送、固定失败话术（依赖全部可注入） |
| `scripts/jm-fetch-one.mjs` | **唯一网络边界**：调边车 API（health/search/download/pdf）、下载任务轮询、整本 PDF 落盘；stdout 最后一行 JSON、日志走 stderr |
| `scripts/selftest-jm.js` | 合成判据（30 例）：解析、边车契约（假 fetch，含 `/pdf`）、白名单/冷却/失败兜底、单本合并/多本清单、PDF 发送失败、接线哨兵 |
| `src/config.js` / `src/config-params.js` / `.env.example` | 配置项与参数目录登记（默认关闭、启动不联网） |

测试入口（不联网、不启动 bot）：

```sh
node scripts/selftest-jm.js
node scripts/selftest-public.js
```
