# 公开架构说明


本文面向两类读者：想在自己环境里部署这个 bot 的人，以及想改公共代码（bot 核心、搬图、测试）的外部贡献者。它讲清四件事：代码怎么分区、一条消息在进程里怎么走、模块边界在哪、想加东西（图源 / 内容 / 新平台）该动哪里。

**范围声明**：公开集是维护仓（发布来源）经过清单筛选后的子集，不含网页面板、官方角色内容与素材、真实别名表、图库、收款码和私人运行数据。本文描述**这份公开代码**，不描述私有部署，也不承诺未公开能力。行为以当前提交的代码与测试输出为准。

配套阅读：平台对抗与权限细节见 [docs/01-平台对抗手册-QQ](<01-平台对抗手册-QQ.md>)，可移植性契约见 [docs/02-架构与适配器契约](<02-架构与适配器契约.md>)，通道容量/过期策略见 [docs/17-通道策略表](<17-通道策略表.md>)，命令与关键字见 [docs/命令与关键字](<命令与关键字.md>)。

## 1. 三区：P 程序 / C 内容 / D 数据

所有文件按"种类"归入三个区。**区是种类，不是可见性**——官方角色也属于 C，只是"不公开的 C"。

| 区 | 是什么 | 典型内容 | 可见性 |
|---|---|---|---|
| **P 程序** | 机制与工具 | `src/`（含 `src/play/`、`src/vendor/`）、`scripts/`、`bots/demo/`、`.github/`、根目录程序文件 | 公开集里的主体 |
| **C 内容** | 可替换的展示内容 | 角色/世界/规则/主题/知识内容，部署者本地提供的 JSON 覆盖 | 每个作者自选；公开集不带官方内容 |
| **D 数据** | 运行期产生的数据 | 记忆、存档、账号、日志、备份、密钥、运行配置 | 永远私有，不进 Git |

依赖必须单向：**P 不 import 仓内任何 C/D 文件**；C 只基于 P 暴露的接口扩展；D 由 P+C 运行产生，不被程序 import。

这条规矩是机器化的：维护仓用三区清单 + 校验器逐条检查 P 区文件的相对 import，越界即红。公开集里保留了工具本体、可当写法参考：

- `scripts/zone-check.mjs`：清单校验（归属唯一、P→C/D 越界 import；自带 `--selftest`）。
- `scripts/export-dry-run.mjs`：导出预演（只算"会出去哪些"，不复制文件）。
- `scripts/export-public.mjs`：按清单把候选导出到仓外目录（不复制 Git 历史）。
- `scripts/scan-public-leaks.mjs`：对"将公开"的正文做可机器识别的泄露形态扫描（私有盘符路径、内网域名、AppID/openid/密钥前缀等）。

清单本身（维护仓里的 `zone-manifest.json`）描述的是**未公开文件集**，所以不随公开集分发。给贡献者的实践含义只有一句：新增文件先在维护仓清单里归位，再谈公开；不要在公开侧"按目录猜"补文件。

## 2. 一次消息的旅程（主线数据流）

以群聊里 @ 机器人为例，主链路如下（括号内是真实文件，均相对仓根）：

1. **平台事件**：`src/qq.js` 的 `QqGateway` 维持 QQ 网关长连接（心跳、重连、事件分发），`TokenManager` 管令牌，`QqApi` 管发送。QQ 专属协议细节全部收在这一层。
2. **归一化**：`normalizeDispatch()` 把平台事件转成统一的 `message` 对象——`{ scene, targetId, senderId, senderName, messageId, replyToMessageId, content, images, isMention, mentions, timestamp }`；不是消息的事件返回 `null`。**下游只消费这个结构**，这是适配器契约的核心（详见 [docs/02-架构与适配器契约](<02-架构与适配器契约.md>)）。
3. **接入闸门**：`src/index.js` 的 `handleMessage()` 依次做：搬运（聊天记录转 PDF）分支 → 别的 bot 的消息过滤 → 已知群落库 → 发送者准入（`allowlist` 空名单即拒绝；`blocklist` 空名单等于全开）→ 指标与"认识的人"/事实/数值结算。
4. **合并与节奏**：`src/burst-queue.js` 把连发消息攒成一轮；`src/group-context.js` 管对话窗口、@ 判定、关键词；`src/turn-policy.js` 按场合给输出策略。
5. **分支**：命令类消息走 `src/commands.js` 的命令表与 `src/index.js` 的各命令处理器，直接回；搬图请求走 `src/meitu-command.js`（纯解析）→ `src/meitu-service.js`（编排、冷却、子进程抓图、上传发送）；其余进入模型轮。
6. **上下文装配**：`src/engine.js` 的 `createOwnEngine()` 负责组装——人设（工作区下的 `AGENTS.md`）→ 摘要区 → 历史 → 本轮，所有注入块必须经 `src/inject-mark.js` 包裹，超预算时由 `src/context-budget.js` 裁剪。记忆检索来自 `src/memory-store.js`（SQLite + FTS）。
7. **模型调用**：`src/llm.js` 的 `createLlmClient()` 直连 OpenAI 兼容 HTTP 端点，负责并发队列、退避重试、超时、错误分类与 usage 带出；模型档位由 `src/model-slots.js` / `src/llm-settings.js` 管理。
8. **出站**：清洗（`sanitizeOutgoingText()`、`src/control-markup.js` 去内部标记）→ 分条（`src/burst.js`、`src/mood.js` 的 `splitSpokenLines()`）→ 发送（`QqApi`；被动回复带 `msg_id`/`msg_seq`，主动消息受平台配额约束）。
9. **落库与观测**：`src/sqlite-store.js`（`state.db`：会话、数值、群与人的名册、账本、出站留痕等）、`src/memory-store.js`（`memory.db`：轮次、摘要、记忆块）、`src/metrics.js` / `src/usage-account.js` / `src/log.js`（指标、用量、日志）。
10. **后台拍**：暖群 `src/warmup.js`、主动生活 `src/selfcare.js`、早安 `src/morning.js`、记忆归档 `src/memory-archive-tick.js`、版本播报 `src/announce-flow.js` 等定时逻辑，和消息链共用同一份状态库与发送通道。

一句话概括：**平台事件先归一化，再进内核；内核只认统一 `message` 与自己维护的状态；所有出站最终归到同一个发送通道。**

       └─ src/index.js main()（装配状态库、模型、锁、通道、后台拍）
            ├─ src/qq.js        通道适配（QQ）
            ├─ src/engine.js    回合内核（自有引擎）
            ├─ src/llm.js       模型客户端（OpenAI 兼容 HTTP）
            ├─ src/sqlite-store.js / src/memory-store.js  状态与记忆
            └─ scripts/meitu-fetch-one.mjs（子进程）       搬图抓取

| **内容默认值** | `src/local-turn-content.js`、`src/local-gameplay-content.js`、`src/local-mood-body-content.js`、`src/local-story-world-content.js`、`src/local-infra-content.js` | 读取可选的本地内容文件；缺失时用代码内的中性默认 |
| **工具与自测** | `scripts/selftest.js`、`scripts/selftest-public.js`、`scripts/simulate-engine.mjs`、`scripts/replay-engine.mjs`、`scripts/economy-sim.js`、`scripts/verify-qq.js`、`scripts/verify-llm.js`、大量 `scripts/selftest-*.js` 套件 | 公开/全量测试分流、套件自跑入口、引擎生命周期模拟与历史回放、经济标定、联网定向探针 |
| **第三方算法副本** | `src/vendor/jpeg-decoder.js` | 逐字引用 jpeg-js 的解码器（Apache-2.0，文件头保留来源与许可）；仅用于小图放大，不是 npm 依赖 |

关键纪律（改代码前先知道）：

- **零第三方运行依赖**：`package.json` 没有 `dependencies`，只用 `node:` 内置模块与 `src/vendor/` 里的算法副本。新增依赖要先过供应链评审，别为了提高一点便利破这条。
- **网络集中在少数边界**：模型在 `src/llm.js`；搬图的图源检索与下载在 `scripts/meitu-fetch-one.mjs`（被 `src/meitu-service.js` 以子进程调用，真实 `fetch` 由 CLI 注入）；平台在 `src/qq.js`。其余模块尽量做纯函数，测试用注入的假 `fetch` / 假时钟。
- **单实例锁**：每个运行进程必须独占自己的 `.env`、工作区、home、状态库、锁文件、日志与图片目录；多实例是"多套目录"，不是复制后直接起。
- **数据不进 Git**：`data/` 与本地内容都在 `.gitignore` 内；公开仓里没有 `data/`、没有 `content/`、没有 `.env`。

## 4. 模块边界表（目录 → 职责 → 依赖方向）

| 路径 | 职责 | 允许依赖 | 禁止 |
|---|---|---|---|
| `src/*.js`（内核与通道） | 运行期机制 | Node 内置、`src/` 内 P 文件、`src/vendor/` | import `content/`、`data/`、`docs/` 或任何具体角色文件 |
| `src/play/` | 玩法 reducer（`applyAction` 类型化动作协议） | 纯 JS + 同目录纯函数 | 不碰 QQ/HTTP/`state.db`；时间与随机从 `ctx` 注入 |
| `src/vendor/` | 逐字引入的第三方算法（带许可头） | 无（纯算法） | 不触网络/文件系统；不扩写成框架 |
| `src/local-*-content.js` | 读取固定路径的可选本地内容（非发现式加载、非代码） | Node 内置 `fs`；固定 `content/local/*.json` 路径 | 不扫描目录、不执行内容、不做合并层 |
| `scripts/launch.js`、`scripts/selftest*.js` 等 | 入口、测试、诊断、导出工具 | `src/` 与 Node 内置 | 不得写运行时 `data/`（测试只用独立临时目录） |
| `scripts/meitu-fetch-one.mjs` | 独立抓图 CLI（网络只在这里） | `src/` 纯函数 + 由 CLI 注入的真实 `fetch` | stdout 只留最后一行 JSON；日志走 stderr |
| `bots/demo/run.cmd` | 纯 ASCII 启动包装器，定位仓根、显式选 `.env` | `scripts/launch.js` | 不含逻辑、不写其他实例路径 |
| `docs/` | 公开文档（本页、平台手册、适配器契约、通道策略、命令表） | 无代码依赖 | 不链私有文档/内部记录 |
| `.github/` | CI 与协作模板 | 无 | CI 只跑公开子集；权限只读 |
| `data/`、`content/`（本地自建） | D 区运行数据 / C 区内容覆盖 | 由程序读写 | 永不入库、永不随公开集分发 |

一个刻意保留的跨界点：`src/meitu-service.js` 用**子进程**调 `scripts/meitu-fetch-one.mjs`。这是有意的进程边界（网络与落盘隔离出去、CLI 可单独测、结果用单行 JSON 回传），不算"P 依赖 scripts"的违规；改它时保持这个契约：**父进程只认 stdout 最后一行 JSON，失败也由 JSON 表达（退出码不承载语义），日志一律走 stderr**。

## 5. 扩展点

### 5.1 加一个图源（最常见的外部需求）

现有实现把"图源"当成数据而不是分支逻辑：URL 构造、返回归一化、分级过滤、去重都在纯函数层，网络在 CLI 层。加一个源的最小改动面：

1. `src/meitu-search.js`：加 `build<源>Url()`、`normalize<源>Post()`（统一形状：`{ source, id, rating, tags, url, ext, md5, score, width, height }`），把该源的分级名映射进既有过滤口径；必要时扩展 `buildRungs()` 的候选链。
2. `scripts/meitu-fetch-one.mjs`：`--source` 接受新值，接上 `rungUrl()`/`fetchJson()`；保持"stderr 记日志、stdout 最后一行 JSON"的既有形状。
3. `src/config.js`：`QQBOT_MEITU_SOURCE` 的合法值列表加新源；同步更新 `.env.example` 注释。
4. `scripts/selftest-meitu-fetch.js`：用假 `fetch` 补归一化/过滤/去重用例（不联网）。该文件只导出注册函数，请通过公开入口 `node scripts/selftest-public.js` 运行；交付前四组合 CI 跑同一入口。
5. 不需要动 `src/meitu-service.js` 的编排（除非新源需要特殊代理/超时策略）。**必须继续满足**：扩展名白名单、单张大小上限、超时、内容分级与标签黑名单 fail closed、按 md5/游标去重、按群冷却。

### 5.2 加内容 / 换主题（当前形态，不是稳定包格式）

- 主题标识走 `QQBOT_MOOD_THEME` 与 `QQBOT_BODY_THEME`（两者必须一致；demo 用 `demo`）。数值框架由 `src/body-rules.js` 选，展示措辞由 `src/body-theme.js` / `src/mood.js` 的表决定。
- 部署者可以在本地放 `content/local/*.json`（如 `turn-lines.json`、`gameplay.json`），由 `src/local-*-content.js` 校验后读取；缺失/非法时回退到代码内中性默认，不会静默换成别的实例内容。
- 经历/节日/伙伴/故事事件这类"角色内容"当前是代码内登记表 + 可选本地 JSON 的组合（`src/character-days.js`、`src/companions.js`、`src/story.js`、`src/story-content.js`）。
- ⚠️ **正式的"角色内容包"格式尚未定型**（路线图上的后续项）。现在新增角色通常要动 P 区登记表，走 PR 流程；不要把当前本地 JSON 当稳定 ABI。等包格式落地后，本节会替换成正式的包目录结构说明。

### 5.3 加一个聊天平台适配器

可移植性契约在 [docs/02-架构与适配器契约](<02-架构与适配器契约.md>)：新平台必须提供四件事——令牌获取/刷新、事件流（含心跳/重连/去重）、发送（被动与主动、分片）、媒体（下载与上传）——并且**归一化成同一份 `message` 结构**。归一化完成后，下游的准入、场合策略、对话窗口、冷却、模型调用、出站清洗理论上零修改复用。（进程模型两页同一口径：本页第 3 节给总览，那篇第 1 节讲单进程与子进程边界。）

老实说：现在只有一个平台实现，`src/index.js` 的接线仍带 QQ 假设，没有为"第二个平台"提前抽象。真要接第二个平台时，正确顺序是先把 `QqGateway` 形状的事件源做出来、让下游只认统一结构，再回头抽公共接口；不要凭空设计一套通用适配器。

### 5.4 加一条玩法 / 命令

- 玩法：在 `src/play/action.js` 声明动作种类，在 `src/play/index.js` 的派发表加一行 reducer；`applyAction()` 对未声明动作 fail closed。玩法 reducer 必须保持纯函数（`{ state, events, lines }`，时间随机从 `ctx` 注入），这样 QQ 与以后的其他前端可以共用同一份判定。
- 命令：命令表在 `src/commands.js`（含公开视图），`docs/命令与关键字.md` 由 `scripts/command-index.js` 生成、测试比对；改命令要连文档一起重生成，否则测试变红。

## 6. 明确不在公开范围的东西

- **网页面板 / 官方 UI / 聊天网页**：公开集不包含面板与网页模块。相关开关（模板里显式置 `false`）只是兼容配置；打开而缺文件时启动会**明确报错**，不会用空功能假装可用。
- **官方角色内容与素材**：角色卡、皮肤、图库、官方文案不在公开集；公开侧随代码提供的是中性示例（`demo` 主题、中性句库与占位素材）。
- **真实数据**：真实别名表、真实图库、收款码、账号、密钥、日志、会话库、私人运行数据一律不公开，也不要通过 Issue/PR 提供。
- **私有运维与内部记录**：部署脚本、内部任务板、交接记录、决策日志不属于公开集；本页不链接它们。

如果拿到的是公开集，发现某个可选能力缺文件：按 README 关掉对应开关并以公开集为准，不要从别处补私有文件。

## 7. 已知边界与验证口径

- **运行环境**：Node.js 22 或更高（需要内置 `fetch`、`WebSocket`、`node:sqlite`）；无 `npm install` 步骤。
- **公开自测是隔离子集**：`node scripts/selftest-public.js` 只用合成 fixture、假网络响应与临时目录，不读你的 QQ/模型凭据、不启动 bot、不访问真实图源。它**不是**全量回归的替代品；`node scripts/selftest.js` 默认要求完整私库，缺件即报错，只有显式 `--public` 才走公开子集。
- **CI 证明什么**：`.github/workflows/public-selftest.yml` 在 Ubuntu/Windows × Node 22/24 四组合跑公开子集。它证明公开代码在这几个环境可加载、公开用例通过；**不证明**真实 QQ、模型端点或图源链路可用。
- **存储形态**：每个实例一组本地 SQLite 文件（`state.db`、`memory.db`，启用搬图时还有图库元数据库），单写者；备份与迁移由部署者负责。
- **尚未完成 / 不承诺**：网页拆分公开、角色内容包正式格式、多 bot 共享世界服务、覆盖率或质量门。看到代码里有相关入口不代表公开集已支持。
- **许可边界**：代码是 MIT，但模型、QQ 平台与图源各自有条款；图片、角色或其他第三方内容的授权不随代码许可转让。

## 8. 名词速查

| 词 | 含义 |
|---|---|
| 区（P/C/D） | 程序 / 内容 / 数据三类；区是种类，不等于公开与否 |
| 通道 | 一条消息通路（被动回复、主动发言、位置报备、摘要…），容量与过期策略见 `src/channel-policy.js` |
| 会话 | 按"私聊对象或群"切分的上下文单元，状态与记忆按会话隔离 |
| 轮（turn） | 一次"用户说了 → 模型答了"的处理单元 |
| 记忆块 / 摘要 | 长期记忆的固化条目 / 滚动压缩的会话摘要，二者分开存 |
| 搬图 | 按"发 N 张某角色图"这类指令，由代码检索、过滤、下载、发送，正常命中不经过模型 |
| 主题 | `mood` / `body` 的展示口径标识，实例配置里成对出现 |
| 工作区 | 放 `AGENTS.md` 人设与本地内容的目录，由 `QQBOT_WORKSPACE` 指定 |
