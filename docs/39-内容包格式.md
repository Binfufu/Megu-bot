# 内容包格式

内容包（content pack）是一份**纯 JSON 数据**，用来描述一个角色的展示内容：情绪表、身体/数值的文案、风格短句、故事角色段和纪念日。它不包含代码，也不改变程序的行为逻辑；程序只负责发现、校验并读取包里的数据。

本文面向想自己写内容包的外部作者，说明目录结构、字段语义、最小步骤，以及"写坏了会怎样"。

---

## 1. 内容包是什么

- **它是 C 区数据。** 包只是一棵 JSON 对象树，放在 `content/packs/<id>/pack.json`。程序不会执行、`import`、`eval` 或以模板方式渲染包里的任何字符串；包也不能联网或读取别的文件。
- **程序只认包，不认具体角色。** 机制（情绪怎么切换、数值怎么结算、提示词怎么拼）仍在程序里；包只提供这些机制要展示的文案与 id 清单。
- **一个包 = 一个角色。** 包里集中放这个角色的情绪、身体主题、风格短句、故事角色段与纪念日。世界级共享内容（地点、世界文案、编年史、通用命令文案等）**不属于角色包**，当前仍由本地共享内容或中性默认提供。
- **公开集不带官方内容包。** 这里描述的是格式；仓库不发布任何官方角色内容，也不提供下载。

## 2. 目录结构与发现规则

```text
content/
└─ packs/
   └─ example/
      └─ pack.json        ← 一个包只有这一个必需文件
```

- 每个**子目录**是一个包，目录名就是包 id；`pack.json` 里的 `id` 必须与目录名完全一致。
- 发现时按目录名排序，保证加载顺序稳定；点开头的目录（如 `.backup`）与普通文件不参与发现。
- 没有 `content/packs/` 目录时，程序返回"没有包"，继续用旧的本地内容（兼容旧安装，见 §7）。
- 只要 `content/packs/` 存在，其中**任何一个包写坏都会让加载整体失败**，不会静默跳过坏包、也不会拿别的角色内容顶替（fail closed）。

## 3. 最小完整示例

下面的 `content/packs/example/pack.json` 可以直接复制后改字段；它包含全部必填项，是一个能通过校验的最小包（示例 id 与文案均为人工合成）：

```json
{
  "schemaVersion": 1,
  "id": "example",
  "role": { "label": "示例角色" },
  "themes": { "mood": "example", "body": "example", "style": "example" },
  "mood": {
    "label": "示例情绪",
    "ids": ["calm", "cheer"],
    "topics": ["demo"],
    "moods": {
      "calm": { "label": "平静", "directive": "保持平静、简短地回应。" },
      "cheer": { "label": "开朗", "directive": "语气轻快一点。" }
    },
    "topicTable": {
      "demo": { "label": "示例话题", "keywords": ["示例"] }
    },
    "interjections": {
      "calm": ["我先想想。"],
      "cheer": ["好呀。"]
    },
    "kaomoji": [ { "text": "(・ω・)", "tags": ["示例"] } ],
    "interjectionTopicGate": { "好呀。": ["demo"] }
  },
  "body": {
    "label": "示例身体主题",
    "values": {
      "satiety": { "short": "饱", "long": "饱腹", "states": ["有点饿", "刚好吃饱"] },
      "health": { "short": "康", "long": "健康", "states": ["有点累", "精神很好"] },
      "mood": { "short": "绪", "long": "情绪", "states": ["低落", "平静"] },
      "stamina": { "short": "力", "long": "体力", "states": ["乏力", "还有余力"] },
      "mana": { "short": "魔", "long": "魔力", "states": ["见底", "充盈"] }
    },
    "action": { "verb": "做", "short": "动手", "prompt": "做个动作", "tag": "demo" },
    "growth": {
      "knownAs": "示例称谓", "conceptAs": "示例概念",
      "personRecorded": "已认识示例角色", "conceptRecorded": "已记录示例概念"
    }
  },
  "style": { "nudges": ["回答保持简短。"] },
  "story": { "pack": { "id": "example", "label": "示例故事段" }, "phrases": [ { "phrase": "示例短语", "note": "示例备注" } ] },
  "companion": null,
  "characterDays": [ { "month": 1, "day": 1, "label": "示例纪念日", "source": "示例来源" } ]
}
```

## 4. 字段说明

所有对象都**按精确字段校验**：必填字段一个不能少，**多写一个未知字段也会报 `schema` 错误**。字符串都必须非空（去掉首尾空白后长度大于 0）。

### 4.1 顶层

| 字段 | 必填 | 语义 |
|---|---|---|
| `schemaVersion` | 是 | 目前只接受数字 `1`。 |
| `id` | 是 | 包 id，必须等于目录名；只允许小写字母、数字、`_`、`-`，且以字母或数字开头。 |
| `role.label` | 是 | 人类可读名。仅用于日志/报表，**不参与提示词**。 |
| `themes.mood` / `themes.body` / `themes.style` | 是 | 该包提供的三个主题标识符，运行时按它们选择内容；通常都填成包 id。 |
| `mood` | 是 | 情绪表，见 4.2。 |
| `body` | 是 | 身体/数值展示，见 4.3。 |
| `style.nudges` | 是 | 非空字符串数组：给模型的风格短句。 |
| `story` | 是 | 故事角色段与固定短语，见 4.4。 |
| `companion` | 是 | 伙伴元数据，可为 `null`，见 4.5。 |
| `characterDays` | 是 | 纪念日数组，可为 `[]`，见 4.5。 |

### 4.2 `mood`

| 字段 | 必填 | 语义 |
|---|---|---|
| `label` | 是 | 情绪表的人类可读名。 |
| `ids` | 是 | 情绪 id 清单，**顺序即运行期顺序**；不可重复，不可为空。 |
| `topics` | 是 | 话题 id 清单；不可重复，不可为空。 |
| `moods` | 是 | 以情绪 id 为键的对象，**键集合必须恰好等于 `ids`**；每项 `{label, directive}`。 |
| `topicTable` | 是 | 以话题 id 为键的对象，**键集合必须恰好等于 `topics`**；每项 `{label, keywords[]}`，`keywords` 非空。 |
| `interjections` | 是 | 以情绪 id 为键的对象，**键集合必须恰好等于 `ids`**；值为非空字符串数组（该情绪的插话）。 |
| `kaomoji` | 是 | 非空数组，每项 `{text, tags[]}`，`tags` 非空。 |
| `interjectionTopicGate` | 是 | 插话 → 允许话题 id 数组的门控表；键必须是 `interjections` 里真实出现过的句子，值里的每个话题 id 也必须在 `topics` 里。 |

### 4.3 `body`

| 字段 | 必填 | 语义 |
|---|---|---|
| `label` | 是 | 身体主题的人类可读名。 |
| `values` | 是 | 必须恰好包含 `satiety`、`health`、`mood`、`stamina`、`mana` 五个键；每项 `{short, long, states[]}`，`states` 为非空字符串数组。 |
| `action` | 是 | `{verb, short, prompt, tag}` 四个非空字符串。 |
| `growth` | 是 | `{knownAs, conceptAs, personRecorded, conceptRecorded}` 四个非空字符串。 |

### 4.4 `story`

| 字段 | 必填 | 语义 |
|---|---|---|
| `pack` | 是 | 角色故事段：`{id, label}`，或 `{id, label, events}`。 |
| `pack.events` | 否 | 若出现必须是非空数组；每项 `{id, setup, branches[]}`，分支为 `{id, weight>0, line, keywords[], effect}`。 |
| `pack.events[].branches[].effect` | — | 只允许 `money`/`satiety`/`health`/`mood`/`stamina`/`mana` 六个键，值为有限数字。 |
| `phrases` | 是 | 固定短语数组（可为空），每项 `{phrase, note}` 均为非空字符串。 |

带事件的故事段片段示例：

```json
{
  "story": {
    "pack": {
      "id": "example",
      "label": "示例故事段",
      "events": [
        {
          "id": "first_meeting",
          "setup": "在示例地点第一次见面。",
          "branches": [
            {
              "id": "warm",
              "weight": 1,
              "line": "示例：她先打了招呼。",
              "keywords": ["示例"],
              "effect": { "mood": 1, "stamina": -1 }
            }
          ]
        }
      ]
    },
    "phrases": []
  }
}
```

### 4.5 `companion` 与 `characterDays`

`companion` 为 `null`，或一个自洽的伙伴对象：

| 字段 | 语义 |
|---|---|
| `id` / `name` / `fullName` / `blurb` | 非空字符串；`id` 决定 `theme`、`bot`、`stateDir`。 |
| `theme` / `bot` / `stateDir` | 必须都等于 `companion.id`。 |
| `art` | 头像文件名，只允许单层文件名且以 `.png` 或 `.jpg` 结尾（如 `example.png`）；**不允许路径分隔符**。 |

`characterDays` 是数组（可为空），每项 `{month, day, label, source}`：`month` 是 1–12 的整数，`day` 是 1–31 的整数，`label`/`source` 为非空字符串。

```json
{
  "companion": {
    "id": "example",
    "name": "示例",
    "fullName": "示例角色",
    "theme": "example",
    "bot": "example",
    "stateDir": "example",
    "art": "example.png",
    "blurb": "示例说明：这是一段人工合成的占位描述。"
  },
  "characterDays": [
    { "month": 1, "day": 1, "label": "示例纪念日", "source": "示例来源" }
  ]
}
```

### 4.6 主题标识符怎么生效

运行配置里的主题标识（例如情绪主题、身体主题、风格主题的环境变量）决定**取哪一份内容**；包里的 `themes.*` 是这份内容登记的名字。一个包通常把三个值都设成自己的包 id，并在运行时把对应配置也指向它。

- 多个包若登记了**同一个主题标识**，先被发现的包生效；不要在多个包里复用同一个主题标识，给每个包用唯一 id。
- 主题标识只是选择键，不是"安装"动作；不需要改程序，也不需要额外注册文件。

## 5. 新增一个包的最小步骤

1. 决定包 id，例如 `example`；它必须满足 `^[a-z0-9][a-z0-9_-]*$`，并会成为目录名。
2. 创建 `content/packs/example/pack.json`，从 §3 的示例复制，替换掉示例文案与 id。
3. 核对 `id` 与目录名一致、`themes.*` 与你准备使用的运行配置一致。
4. 每次改动后跑一次公开自测，确认没有破坏加载器契约：
   `node scripts/selftest-public.js`
5. 启动 bot 时观察日志：包写坏会**直接报错并给出包 id 与错误码**，不会启动成"用了别的角色内容"的样子。

> 包里的文案会进入提示词或界面，请只写你确认过、有权使用的内容；不要放凭据、真实用户数据或别人的私有角色内容。

## 6. 校验与失败行为

| 情况 | 行为 |
|---|---|
| 没有 `content/packs/` 目录 | 视为"没有包"，回退旧的本地内容（旧安装行为不变）。 |
| 目录存在，但某个包缺 `pack.json` | 抛错，错误码 `missing-pack-file`。 |
| `pack.json` 不是合法 JSON | 抛错，错误码 `invalid-json`。 |
| JSON 合法但结构不符 | 抛错，错误码是出问题的字段名（`schema`、`schema-version`、`id`、`role`、`themes`、`mood`、`body`、`style`、`story`、`companion`、`characterDays` 之一）。 |
| `id` 与目录名不一致 | 抛错，错误码 `id-mismatch`。 |
| 同一次发现里出现重复 id | 抛错，错误码 `duplicate-id`。 |
| 读取文件本身失败（如权限） | 抛错，错误码是操作系统码（如 `EACCES`）或 `READ_ERROR`。 |

- 错误信息形如 `content pack "example": mood`，**只包含包 id 与错误码**，不回显包内容或绝对路径；排查时按错误码对照上表即可。
- **包内容永不执行代码。** 加载器只做目录发现 + 读一个 JSON 文件 + 结构校验；不 `import`、不 `eval`、不做模板渲染、不联网。
- **不静默降级。** 坏包不会让程序悄悄换成另一个包或中性内容；宁可启动失败，也不让运行中的角色内容和作者预期不一致。

## 7. 与 `content/local/` 旧内容的关系

早期安装把展示内容放在 `content/local/` 的固定 JSON 文件里。现在的优先级是：

- 有 `content/packs/` 时，角色内容来自包；
- 没有时，回退旧的 `content/local/` 文件（这就是"缺目录返回空、继续用旧内容"的兼容路径）。

**作为包作者，你不需要改 `content/local/`。** 它只是旧快照与回退位置；官方内容也不随仓库公开。旧快照的后续移除属于包生命周期工作，当前版本不要假设它不存在。

## 8. 明确不承诺什么

- 不提供内容包的安装、升级、卸载、下载或交换市场；本文只定义格式与读取契约。
- 不公开任何官方角色包；公开集只有程序与中性示例。
- 世界级共享内容（地点、世界文案、编年史、通用命令文案等）尚未包化。
- 格式版本目前是 `schemaVersion: 1`，尚未冻结；升级包格式时以项目 CHANGELOG 与发布说明为准，不承诺旧包永远可用。
- 内容包不改变情绪/数值策略、随机数或提示词结构；它只替换被机制消费的展示数据。
- 公开节点不提供网页界面；包内容在网页端的呈现不属于当前承诺。
