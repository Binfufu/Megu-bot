# 公开路线图

> 本文只描述方向和已知的取舍，不是发布承诺，不含日期和工期。已发布内容以 [Releases](https://github.com/Binfufu/Megu-bot/releases) 与 [CHANGELOG](../CHANGELOG.md) 为准；已知边界见 [公开架构说明](37-公开架构说明.md) 第 7 节。

## 已交付（公开 v1）

- QQ 官方开放平台 bot 框架：出站 WebSocket 收事件，OpenAPI 发消息，无需公网入站端口。
- 代码层搬图：检索、下载、发送由代码执行，不交给模型；默认关闭。
- 角色级内容包、世界级世界包与类型化参数系统（[内容包格式](39-内容包格式.md)、[世界包格式](42-世界包格式.md)、[参数系统](41-参数系统.md)）。
- 玩法内核是不依赖 QQ 的纯函数 reducer（`src/play/`），可以离线模拟。
- 零第三方运行依赖；离线公开自测，CI 在 Ubuntu 与 Windows、Node 22 与 24 上运行。

## 明确不在公开集

网页面板、官方角色内容与素材、真实别名表、图库、收款码、凭据和任何私人运行数据。这些不是“尚未完成”，而是不随公开集发布。

## 贯穿所有方向的原则

- **程序、可交换内容、私人运行数据三类分开**，依赖只能单向：程序不 import 具体角色或世界，内容包和世界包只放数据、不执行代码。
- **规则要能测**：影响结果的硬规则写成确定性的纯函数或闸门并配判据；只写进提示词的约定不算已生效。
- **校验失败就拒绝**：非法输入在连接 QQ、调用模型之前报错，错误只含固定码和已登记的 id，不含内容片段、路径或密钥。
- **保持零第三方运行依赖**；新增依赖要先过供应链评审。

## 可能的后续方向（未排期，不承诺）

### 1. 多 bot 共享世界

- **现状**：每个 bot 实例各有一套本地 SQLite，世界并不共享。玩法 reducer 已与 QQ 解耦，但 `src/index.js` 的接线仍带 QQ 假设，现在只有一个平台实现（见公开架构说明 §5.3）。
- **设想**：数据分四层作用域：实例级（部署配置、密钥、日志）、世界级（地图、规则、公共事件）、bot 级（存档、记忆、关系）、用户级（账号、授权、配额）。存储可以先用单个 SQLite，但访问必须经过世界服务；最小形态是一个进程、WAL 模式、单写者串行落库。bot 只提交“意图”，由世界校验后结算，不直接拿数据库连接。
- **谁说了算**：世界状态以世界为准；人格、模型和私人记忆留在 bot 自己一侧。双方只交换世界可见的事实，不交换私聊内容。轻量 NPC 默认用模板、规则或小模型，不默认调用大模型。
- **未决**：并发写怎么仲裁；bot 掉线后它在世界里的位置是停住、只读还是由 NPC 代替；世界接口版本不兼容时怎么降级；写入扛不住时迁到什么存储，在没有真实负载数据前不会先上集群。

### 2. 基础网页客户端

- **现状**：公开集没有网页，配置里必须保持 `QQBOT_PANEL=false`。入口文件 `src/index.js` 里仍保留按开关动态加载网页模块的接线，这些模块不在公开集里，所以真正解耦要等一次单独的拆分。设计上 QQ 只是适配器之一，bot 不必依赖前端。
- **设想**：世界铺满页面，聊天等栏位叠加在上面；跳转是移动镜头而不是换页。镜头只是客户端的视图状态，世界真相（位置、场所、事件）留在服务端。镜头目标写进 URL，刷新、后退和分享都能回到同一处。窄屏可玩、键盘可操作、提供文字视图兜底、尊重减少动效。
- **未决**：基础客户端和可替换的官方界面在哪里分界；它以什么形态、什么时间进入公开集。

### 3. 数值与成长设计

- **设想**：只存底层资源（例如身体能量、精神电量），外显数值是由纯函数算出的派生视图，世界事件只作用于底层；对外继续用档位表达，不报裸数字。先天属性在创建时按预算分配，之后基本固定；能力不靠加数值增长，等级给的是新分支、新动作和自定义槽。自定义必须有取舍（范围大则冷却或消耗变差，方向多则单次变弱，特效只做表现），否则会变成变相的数值膨胀。属性洗点按账号计，免费一次，之后只花游戏内货币，不接真实货币。
- **为什么这样**：能力数值一旦自增，新增能力会稀释旧值，训练变成零和，老内容会因数值膨胀失效。
- **未决**：等级上限和经验来源；分支能否多修；内容难度是否也水平化；新玩家如何追上已推进的世界。

### 4. 自部署 bot 接入托管世界

- **设想**：别人自己部署的 bot 通过世界服务的接口接入，不拿数据库连接。每个动作带签名和幂等键，由世界侧验证，不信任自报身份；默认最低权限，可随时撤销。所有输入做 schema 校验、多维限流并留审计记录；接口只收数据和意图，不执行外部代码。解绑等于离开世界，当前状态可以被新状态覆盖，事件流水和贡献账本只追加，防止世界进度被回滚或重复刷。经济权限与普通玩家相同，防滥用针对行为而不是身份。
- **未决**：开放注册的防滥用做到哪一档；违规如何处罚、谁处理申诉；解绑后世界侧数据归谁；这个方向是否出现在公开集里，取决于上面两项先落地。

### 5. 内容包与世界包的社区交换

- **现状**：只有格式和加载器。世界包“放进目录就是安装，删掉目录就是卸载”，没有安装器、注册表、下载或交换市场（见世界包格式 §6、§10）；格式版本 `schemaVersion: 1` 尚未冻结，不承诺旧包永远可用（§10）。
- **未决**：包的来源与审核；内容授权如何标注（代码的 MIT 许可不覆盖第三方内容）；包格式升级时对旧包的兼容承诺；如何继续保证包只含数据。

### 6. 工程质量与上手体验

- **测试**：公开自测目前是 12 个套件的隔离子集，不覆盖网页、真实 QQ 链路和真实图源；覆盖范围的变化会同步写进 CONTRIBUTING 的覆盖清单。
- **类型**：大文件逐步加 JSDoc 类型检查，不迁移 TypeScript。检查工具只在开发期使用，不进运行依赖，也不应让“公开自测无需 `npm install`”这条承诺失效。
- **文档**：参数系统已补离线观察示例（见 [参数系统](41-参数系统.md) §2）；单实例的升级与回滚指南还没有。

## 想参与

先读 [贡献指南](../CONTRIBUTING.md)，再用 issue 模板谈范围：每个 PR 都要关联一个 issue，范围外的需求先讨论，不要顺手加入数据导出、生产入口或新依赖。适合先谈的方向：图源适配器示例、文档与示例的可复现问题、公开自测的覆盖补充。请只提交合成复现，不要贴真实图库、别名资料或凭据。
