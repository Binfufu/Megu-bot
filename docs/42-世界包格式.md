# 世界包格式

世界包（world pack）是一份**纯 JSON 数据**，用来描述一个「世界」的共享内容：场所、世界文案、模块文案、编年史与事件标签、通用命令效果文案、暖群话题、搬图话术，以及世界配置与规则文案。它不包含代码，也不改变程序的行为逻辑；程序只负责发现、校验、选择并读取包里的数据。

本文面向想自己写世界包的外部作者，说明目录结构、字段语义、选择规则、装/改/升级/卸的做法，以及"写坏了会怎样"。

---

## 1. 世界包是什么

- **它是 C 区数据。** 包只是一棵 JSON 对象树，放在 `content/worlds/<id>/world.json`。程序不会执行、`import`、`eval` 或以模板方式渲染包里的任何字符串；包也不能联网或读取别的文件。
- **它描述"世界"，不描述"角色"。** 场所、世界文案、编年史分类、通用命令效果、暖群与搬图话术这类**世界级共享**内容属于世界包；某个角色的情绪表、身体主题、风格短句、故事角色段与纪念日属于**内容包**（角色级），格式见 [内容包格式](39-内容包格式.md)。
- **一个包 = 一份世界共享内容。** 同时安装多个世界包是允许的，但运行时只使用**一个激活世界**；其余包仍会被读取与校验，只是不参与本次内容装配。
- **官方世界包不公开。** 公开集只带一个**中性原创示例世界**（`content/worlds/example/`），用于演示格式与跑公开自测；仓库不发布任何官方世界内容，也不提供下载。
- **它是可选层。** 没有任何世界包被激活时，程序继续使用旧版本地共享内容（若部署者提供）或代码内中性默认，行为与未引入世界包时一致。

## 2. 目录结构与发现规则

```text
content/
└─ worlds/
   ├─ example/
   │  └─ world.json        ← 公开集自带的示例世界
   └─ <你的世界 id>/
      └─ world.json        ← 一个包只有这一个必需文件
```

- 每个**子目录**是一个世界包，目录名就是世界 id；`world.json` 里的 `id` 必须与目录名完全一致。
- 发现时按目录名排序，保证加载顺序稳定；点开头的目录（如 `.backup`）与普通文件不参与发现。
- 没有 `content/worlds/` 目录时，程序视为"没有世界包"：不激活世界包，继续走旧的本地内容/中性默认（兼容旧安装，见 §8）。
- 只要 `content/worlds/` 存在，其中**任何一个包写坏都会让加载整体失败**，不会静默跳过坏包、也不会拿别的世界内容顶替（fail closed）。

## 3. 最小完整示例

完整、可直接复制改写的示例就是公开集自带的 [`content/worlds/example/world.json`](<../content/worlds/example/world.json>)（全部必填段齐全，文案均为人工合成）。下面是它的**结构骨架**，只保留各段的键名，便于先看清形状：

```json
{
  "schemaVersion": 1,
  "id": "example",
  "label": "示例世界",
  "default": false,
  "storyWorld": {
    "storyEvents": [ { "id": "…", "setup": "…", "branches": [ { "id": "…", "weight": 1, "line": "…", "keywords": [], "effect": {} } ] } ],
    "storyClosingWords": ["…"],
    "storyClosingExamples": ["…"],
    "storyRespondClosing": "…",
    "storySettleClosing": "…",
    "places": [ { "id": "home", "name": "…", "kind": "…", "travelMs": 60000, "blurb": "…" } ],
    "worldText": { "currency": "…", "questAcceptPrefix": "…", "questAcceptSuffix": "…", "questAcceptPlain": "…" },
    "moduleText": { "burst": { "name": "…", "note": "…" }, "cook": { "name": "…", "note": "…" }, "sword": { "name": "…" } },
    "chronicleKinds": { "meal": "…", "…": "…" },
    "eventLabels": { "found_coin": "…", "…": "…" },
    "chronicleText": { "currency": "…", "manaLabel": "…", "healFailed": "…" },
    "commandEffects": { "/状态": "…", "…": "…" },
    "cardClaimNotes": { "/状态": "…", "…": "…" },
    "keywordGroups": [ { "label": "…", "words": ["…"] } ],
    "opsEffects": { "…": "…" }
  },
  "turnWorld": {
    "warmupTopics": [ { "tag": "general", "text": "…" } ],
    "meituLines": { "groupDisabled": ["…"], "…": ["…"] }
  },
  "moodWorld": {
    "config": { "groupKeywords": ["…"], "reportTargetName": "…", "bodyMismatchNote": "…" },
    "ruleLabels": { "biological": "…", "mechanical": "…" }
  },
  "params": { "QQBOT_MOOD_KAOMOJI_CHANCE": 0.25 }
}
```

> 骨架里的 `…` 不是合法值。写自己的包时，请以示例文件的完整键集为底稿逐个替换文案；少一个键、多一个键或写错类型都会让包被拒绝（见 §8）。

## 4. 字段说明

所有对象都**按精确字段校验**：必填字段一个不能少，**多写一个未知字段也会报 `schema` 错误**。字符串都必须非空（去掉首尾空白后长度大于 0）。

### 4.1 顶层

| 字段 | 必填 | 语义 |
|---|---|---|
| `schemaVersion` | 是 | 目前只接受数字 `1`。 |
| `id` | 是 | 世界 id，必须等于目录名；只允许小写字母、数字、`_`、`-`，且以字母或数字开头。 |
| `label` | 是 | 人类可读名。仅用于展示/日志，**不参与提示词**。 |
| `default` | 是 | 布尔值。仅当没有任何世界被 `QQBOT_WORLD` 指定、且**恰好一个**包写了 `true` 时，它才会被自动选中，见 §5。 |
| `storyWorld` | 是 | 故事/世界段，见 4.2。 |
| `turnWorld` | 是 | 暖群话题与搬图话术，见 4.3。 |
| `moodWorld` | 是 | 世界配置与规则文案，见 4.4。 |
| `params` | 否 | 7 项白名单内的类型化表现参数；不写保持原默认，见 4.5。 |

### 4.2 `storyWorld`

`storyWorld` 必须**恰好**包含下面 15 个键（精确键集合，不能增删或改名）：

| 字段 | 形状 |
|---|---|
| `storyEvents` | 非空数组；每项 `{id,setup,branches}`。`branches` 非空数组，每项 `{id,weight,line,keywords,effect}`：`weight` 为 `>0` 的有限数，`keywords` 为字符串数组（每个元素都是非空字符串），`effect` 只允许 `money`/`satiety`/`health`/`mood`/`stamina`/`mana` 六个键且值为有限数字。 |
| `storyClosingWords` | 非空字符串数组。 |
| `storyClosingExamples` | 非空字符串数组。 |
| `storyRespondClosing` | 非空字符串。 |
| `storySettleClosing` | 非空字符串。 |
| `places` | **恰好 6 条**，`id` 顺序固定为 `home,fishing,guild,canteen,market,gallery`；每条 `{id,name,kind,travelMs,blurb}`，`travelMs` 为 `>0` 的有限数。 |
| `worldText` | `{currency,questAcceptPrefix,questAcceptSuffix,questAcceptPlain}`，四个值均为非空字符串。 |
| `moduleText` | **恰好 10 个键**：`burst,sword,scout,talk,cook,fish,slow,weak,clumsy,nosy`；`burst`/`cook` 每项恰好 `{name, note}`（两个都必填），其余 8 项恰好 `{name}`。 |
| `chronicleKinds` | **恰好 14 个键**：`meal,fed,selfcare,event,story,quest,fish,sell,home,potion,sleep,move,illness,heal`；每个值均为非空字符串。 |
| `eventLabels` | **恰好 7 个键**：`found_coin,someone_treats,sold_loot,bought_staff,tax,lost_pouch,donated`；每个值均为非空字符串。 |
| `chronicleText` | `{currency,manaLabel,healFailed}`，三个值均为非空字符串。 |
| `commandEffects` | **固定 24 个命令键**（见下表）→ 非空字符串，写该命令对世界/角色的效果说明。 |
| `cardClaimNotes` | **恰好 5 个键**：`/状态,/钱包,/更新,/群列表,/成长`；每个值均为非空字符串。 |
| `keywordGroups` | 非空数组；每项 `{label,words}`，`label` 为非空字符串，`words` 为字符串数组（每个元素都是非空字符串）。 |
| `opsEffects` | **固定 26 个脚本键**（与旧快照登记的工具脚本名一一对应，完整清单以示例包为准，键不可增删）→ 非空字符串，写该运维/工具脚本做什么。 |

`commandEffects` 的 24 个固定键：

| 键 | 键 | 键 | 键 |
|---|---|---|---|
| `/重置` | `/状态` | `/成长` | `/钱包` |
| `/熟人` | `/钓鱼` | `/委托` | `/接 <编号>` |
| `/help` | `/重启` | `/更新` | `/发` |
| `/更新 预览` | `/更新 账本` | `/更新 回退` | `/更新 基线 <版本>` |
| `/更新 <编号>` | `/群列表` | `/忘了` | `/旁白测试` |
| `/发图` | `发N张<角色>美图/涩图` | `/认人` | `/绑定` |

### 4.3 `turnWorld`

`turnWorld` 必须**恰好**包含两个键：

| 字段 | 形状 |
|---|---|
| `warmupTopics` | 非空数组；每项 `{tag,text}`，`tag` 只能是 `meal`/`poor`/`rich`/`general`，`text` 为非空字符串；**至少一条 `general`**。 |
| `meituLines` | **恰好 11 个键**：`groupDisabled,cooldown,unregistered,interpretFailed,noResult,sourceDown,uploadFailed,downloadFailed,internal,blocked_apology,blocked_empty`；每项为非空数组，元素均为非空字符串。 |

### 4.4 `moodWorld`

`moodWorld` 必须**恰好**包含两个键：

| 字段 | 形状 |
|---|---|
| `config` | `{groupKeywords,reportTargetName,bodyMismatchNote}`：`groupKeywords` 为非空字符串数组，后两个为非空字符串。 |
| `ruleLabels` | `{biological,mechanical}`，两个值均为非空字符串。 |

### 4.5 可选 `params`

`params` 是参数 id 到数值的平面对象，只能调节表现倾向，**不能包含密钥、账号、权限、预算或路径**。支持项与边界同 [参数系统 §3](41-参数系统.md#3-内容包参数)，只允许下面 7 项：

| id | 类型与边界 | 含义 |
| --- | --- | --- |
| `QQBOT_MOOD_TTL_MS` | 正安全整数，毫秒 | 情绪保留时间 |
| `QQBOT_MOOD_KAOMOJI_CHANCE` | 有限数，0–1 | 颜文字倾向 |
| `QQBOT_STYLE_NUDGES` | 非负安全整数 | 风格提示抽取数 |
| `QQBOT_SPOKEN_MAX_CHARS` | 非负安全整数 | 无情绪决策时的分段字数 |
| `QQBOT_SPOKEN_EMOJI_CHANCE` | 有限数，0–1 | 分段表情倾向 |
| `QQBOT_POKE_REPLY_CHANCE` | 有限数，0–1 | 戳一戳回应倾向 |
| `QQBOT_FACE_REPLY_CHANCE` | 有限数，0–1 | 单表情回应倾向 |

未知键、错误类型、越界值与部署域键（密钥/账号/权限/预算/路径）一律报 `params` 并拒绝。

## 5. 选择与激活规则

运行时只使用**一个**激活世界。选择顺序固定：

1. 环境变量 `QQBOT_WORLD` 非空（空值视为未设）→ 必须是已发现的世界 id；未知 id 报 `unknown-id`。
2. 否则，若**恰好一个**包的 `default` 为 `true` → 选中它。
3. 若有**多个**包的 `default` 为 `true` → 报 `ambiguous-default`（不按目录顺序选赢家）。
4. 否则不激活世界包（`active = null`）：回退旧版本地共享内容/中性默认。

`QQBOT_WORLD` 的取值就是你放在 `content/worlds/` 下的目录名。示例（`.env` 或进程环境，按你的实例配置）：

```dotenv
QQBOT_WORLD=example
```

`.env.example` 里给的是注释示例，默认不启用；想固定使用某个世界时再取消注释并改成你自己的世界 id。

## 6. 装 / 改 / 升级 / 卸

世界包没有安装器、注册表或下载流程：**放进目录就是安装，删掉目录就是卸载**。

| 动作 | 做法 | 生效与回退 |
|---|---|---|
| 装 | 新建 `content/worlds/<id>/world.json`，`id` 与目录名一致；用 `QQBOT_WORLD=<id>` 指定，或让唯一一个包写 `"default": true`。 | 重启 bot 进程后生效。不需要改程序，也不需要额外注册文件。 |
| 改 | 直接编辑 `world.json` 的文案/字段。 | **改字段需要重启进程**才生效（包在启动时读取一次，不热加载）；重启前包未通过校验则启动直接失败。 |
| 升级 | 在本版本内保持 `schemaVersion: 1`，替换文件即可。 | 未知版本（如 `0`、`2`）一律拒绝（`schema-version`），当前版本不提供自动迁移；格式升级以项目 CHANGELOG 与发布说明为准。 |
| 卸 | 删除 `content/worlds/<id>/` 目录；如果它还写在 `QQBOT_WORLD` 里，也要去掉该配置或改成别的已装世界。 | 卸载后若 `QQBOT_WORLD` 仍指向它，启动报 `unknown-id`（fail closed）；不设 `QQBOT_WORLD` 时回退旧快照/中性默认，正常启动。 |

两点必须知道：

- **世界包只属于内容，不是运行数据。** 装/改/升级/卸只动 `content/worlds/` 下的 JSON；不会删除或改写你的运行数据（`data/` 下的状态库、记忆库、日志、配置）。卸载世界包不会让你丢存档。
- **同一时刻只有一个激活世界。** 多个包可以并存，但未被激活的包只是被校验，不参与内容装配；想知道当前装了什么，看 `content/worlds/` 下的目录，而不是运行日志。

## 7. 三区归属（P / C / D）

世界包属于**内容（C 区）**：它是可替换的展示数据，不是程序机制，也不是运行数据。三区只描述"文件种类"，不直接等于公开与否：

| 区 | 世界包相关含义 |
|---|---|
| **P 程序** | 加载器 `src/world-pack.js` 与公开自测等机制代码；不包含任何具体世界内容。 |
| **C 内容** | 世界包本体（`content/worlds/<id>/world.json`）；官方世界包不公开，公开集只带中性示例 `example`。 |
| **D 数据** | 运行期数据，永远私有、不进 Git，也不由世界包读取或写入。 |

依赖方向仍是单向的：程序只读包数据，包不能反向依赖程序实现；详见 [公开架构说明](37-公开架构说明.md)。

## 8. 校验与失败行为

| 情况 | 行为 |
|---|---|
| 没有 `content/worlds/` 目录 | 视为"没有世界包"，回退旧版本地共享内容/中性默认（旧安装行为不变）。 |
| 目录存在，但某个包缺 `world.json` | 抛错，错误码 `missing-world-file`。 |
| `world.json` 不是合法 JSON | 抛错，错误码 `invalid-json`。 |
| JSON 合法但结构与 §4 不符 | 抛错：顶层键或分段的键集合不对报 `schema`，其余按出问题的部分报 `schema-version`、`id`、`label`、`default`、`params`、`story-world`、`turn-world`、`mood-world`。 |
| `id` 与目录名不一致 | 抛错，错误码 `id-mismatch`。 |
| 同一次发现里出现重复 id | 抛错，错误码 `duplicate-id`。 |
| `QQBOT_WORLD` 指向未安装的 id | 抛错，错误码 `unknown-id`。 |
| 多个包都写了 `"default": true` | 抛错，错误码 `ambiguous-default`。 |
| 读取文件本身失败（如权限） | 抛错，错误码是操作系统码（如 `EACCES`）或 `READ_ERROR`。 |

- 错误信息形如 `world pack "example": schema-version`，**只包含包 id 与错误码**，不回显包内容、绝对路径或原始解析器消息；排查时按错误码对照上表即可。
- **包内容永不执行代码。** 加载器只做目录发现 + 读一个 JSON 文件 + 严格结构校验 + 选择激活世界；不 `import`、不 `eval`、不做模板渲染、不联网。
- **不静默降级。** 坏包不会让程序悄悄换成另一个世界或中性内容；宁可启动失败，也不让运行中的世界内容和作者预期不一致。

## 9. 安全边界

世界包**只是数据**，这也是它被允许和角色内容分开、由外部作者编写的原因：

- 包只能放 JSON 文本；**不能提供或改变**密钥、账号、权限名单、预算、模型端点、代理、文件路径或任何部署项。需要这些的配置只能走实例自己的环境变量，不能借世界包注入。
- 包**不能执行代码**，没有脚本、表达式、模板或可执行片段；加载器不加载包内其他文件。
- 包**不能联网**，也不能读取包目录之外的任何文件。
- 包推荐的唯一"调节项"是 §4.5 的 7 个白名单表现参数，类型与边界由程序校验；越界、未知键或部署域键直接拒绝。
- 包里的文案会进入提示词或界面，请只写你确认过、有权使用的内容；不要放凭据、真实用户数据或别人的私有角色/世界内容。

## 10. 明确不承诺什么

- 不提供世界包的安装器、升级器、卸载器、下载或交换市场；本文只定义格式与读取契约，"放目录/删目录"就是全部动作。
- 不公开任何官方世界包；公开集只有程序与中性示例。
- 不提供多世界共享服务、世界切换 API、网页面板或运行时热加载；切换世界靠改配置 + 重启进程。
- 格式版本目前是 `schemaVersion: 1`，尚未冻结；升级包格式时以项目 CHANGELOG 与发布说明为准，不承诺旧包永远可用。
- 世界包不重写世界/玩法/数值算法、RNG 实现或提示词结构；它只替换这些机制要展示的文案与固定 id 清单。
- 公开节点不提供网页界面；世界包在网页端的呈现不属于当前承诺。
