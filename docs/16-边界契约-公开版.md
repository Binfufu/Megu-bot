# 16 · 边界契约(公开集视图) —— 谁拥有 / 什么时候交回 / 怎么交回

> ⚠️ **本页由 `node scripts\contract.js --public --write` 生成,别手改**(数据在 `src\boundary-contract.js`;
> 改数据 → 重新生成 → `node scripts\contract.js --public --check`;页与数据不同步时公开自测会变红)。
>
> **用途**：说明公开集里的共享与隔离边界、状态权威和交回机制；用真实源码锚点核对，不把模型叙述当状态证据。
> 公开视图只渲染**公开集里能真的核对**的边界行；完整工程契约(含网页相关行)是私有全量页 `docs\16-边界契约.md`,不随公开集分发。

| 边界 | 谁拥有(权威) | 交回触发 | 怎么交回 |
|---|---|---|---|
| 机器人实发正文 | **出站唯一咽喉** `sendChunked()`(`src\\index.js`)—— 任何一条真的发出去的消息都从这里走 | 每一条真的发出去的那一刻 | 写 `state.db` 的 `outbound` 表(时间 / 会话 / 对象 / 主动还是回复 / 字数 / 正文,留 30 天) |
| 记忆(轮次 / 摘要 / 标签 / 长期) | **归档管线** `src\\memory-archive.js` → `memory.db` | 每轮结束后按"触发方式"归档一次;启动与每 15 分钟再补收一次 | `turn` / `summary` / `note` 等表;`kind` 决定它进不进长期层 |
| 机器人的身体(钱 / 体力 / 饱食 / 健康 / 心情 / 魔力) | **单行 `stats` 表**(`id = 1`)—— **一只 bot 一份,不按玩家分** | 每次能动数值的动作(吃饭 / 委托 / 睡觉 / 事件结算) | 直接改那一行;每一笔同时写 `stats_event` 流水(编年史与摘要都从流水派生) |
| 钓鱼(钓位 / 鱼篓 / 这一竿) | **按人**:`fishing:<group\|c2c>:<群id\|应用id>:<userId>`(`src\\play\\fishing.js`) | 甩竿 / 收杆 / 结算,每个动作各自落一次 | 按那个 key 读改写;一个人一个钓位 |
| 位置 / 在场("谁在哪") | **按玩家**:`world:player:<playerId>` 一条事实(`src\\player-world.js`);机器人自己的位置是另一条 | 有人移动(`move.to`)/ 机器人出门与到达(位置事实带 TTL) | 写/读 `metas` 里的位置事实;TTL 到期即"不在这儿了" |
| 委托(这一局 / 看板) | **公会看板**:一局挂在看板键上(`quest_board:<…>`) | 接 / 走流程 / 结算 / 放弃 四种动作 | `openQuest()` 起一局,状态挂在看板键上;结算写 `stats_event` |
| 会话键(机器人跟"谁"说话) | `conversationKeyFor(message)`(`src\\index.js`)—— `qqbot-c2c-<openid>` / `qqbot-group-<群id>` | 每条入站消息 / 每次主动发言 | 会话键标识持久对话与记忆归档的 `conversation`;`/重置` 让它进下一"代"(`-g<N>`) |
| 重启后会丢的"内存态" | **进程内存**(`groupContext.knownGroups()`、暖群状态、连发窗口……) | 进程退出/重启 —— 没有交回,直接归零 | ⚠️ **目前没有交回**:重启后要配"重启代数 + 状态重发"；状态恢复仍是明确缺口 |
| 平台配额(几条 / 多快) | **平台**(入站一条消息最多 5 条被动回复)+ **机器人的情绪上限**(普通发言分条发) | 每次要发多条时 | `planSpokenLines()` 统一分条(答话/合并/早安/自发同一份),`sendSpokenLines()` 每段一条并**接续 `msg_seq`**;普通发言超量的段**并进最后一段**(不截断、不转主动配额),只有显式启用的特殊分段动作超限才走主动配额(20/分钟、1000/天) |

## 逐条:容易搞错的那一句 + 凭什么这么写(锚)

### 机器人实发正文
- ⚠️ `memory.db` 的 `turn.reply_text` 是**模型原文**,不是实发 —— 判"机器人到底发了什么"只认 `outbound`
- 锚:`src/sqlite-store.js` 有 `CREATE TABLE IF NOT EXISTS outbound`(**恰好 1 处**)
- 锚:`src/index.js` 有 `recordOutbound({`(**恰好 1 处**)

### 记忆(轮次 / 摘要 / 标签 / 长期)
- ⚠️ `selflife`(机器人自己过日子那一路)**不进长期层**;机器人的话是否"像是人说的"看 `isHumanTurn`
- 锚:`src/memory-archive.js` 有 `export function classifyKind`、有 `export function isSelfLifePrompt`、有 `NON_MEMORY_KINDS`

### 机器人的身体(钱 / 体力 / 饱食 / 健康 / 心情 / 魔力)
- ⚠️ **两个玩家共用机器人一个身体**:A 花的钱、A 扣的体力,B 立刻受影响 —— 这不是 bug,是"机器人只有一个身体"；这里记录的是共享状态口径
- 锚:`src/sqlite-store.js` 匹配 `CREATE TABLE IF NOT EXISTS stats \([\s\S]{0,240}?CHECK \(id = 1\)`

### 钓鱼(钓位 / 鱼篓 / 这一竿)
- ⚠️ 与"机器人的身体"正相反:**钓鱼按人隔离**,所以两个人同时甩竿**不会互相顶掉**、鱼篓也不串号
- 锚:`src/play/fishing.js` 有 `fishing:${scene === 'group' ? 'group' : 'c2c'}:${place}:${userId || 'anon'}`

### 位置 / 在场("谁在哪")
- ⚠️ 游客**没有位置**(不给匿名者编一个身份);机器人的位置 TTL 由 `whereaboutsTtlMs()` 派生
- 锚:`src/player-world.js` 有 `export const PLAYER_WORLD_PREFIX`、有 `world:player:`

### 委托(这一局 / 看板)
- ⚠️ 看板**共享**:A 接了,B 看到的是同一局(可能正是"抢"的玩法);同一条两人同时点「接」的幂等性**没验过**，不能由本页推断并发交互已验收
- 锚:`src/quest-take.js` 有 `export const QUEST_BOARD_KEY_PREFIX = 'quest_board:';`

### 会话键(机器人跟"谁"说话)
- ⚠️ 键是**会话**不是"机器人的身份":私聊里关于对方的事实另用 `self`;机器人**只有一个身体**,不按 QQ 用户分身
- 锚:`src/index.js` 有 `function conversationKeyFor(message)`
- 锚:`src/memory-archive.js` 有 `qqbot-group-<openid> / qqbot-c2c-<openid>`

### 重启后会丢的"内存态"
- ⚠️ "进程在跑" ≠ "这些状态还在":`knownGroups()` 只认**本次进程收到过消息**的群(现场踩过)
- 锚:`src/group-context.js` 有 `knownGroups()`

### 平台配额(几条 / 多快)
- ⚠️ 口语标点清理在**分条之后**(行尾剥 + 段内停顿标点变空格;`～` 保留);段间节拍 = `spoken.baseDelayMs + 字数×perCharDelayMs`±15% 抖(【暂定】)
- 锚:`src/index.js` 有 `const MAX_PASSIVE_SEQ = 5;`
- 锚:`src/mood.js` 有 `export function splitSpokenLines`、有 `CHAT_TRAILING_PUNCT`

## 这一页**不**管什么(免得被当万灵药)

- 它不替代实现代码与专项测试，只记录**边界与权威**。
- 它不保证"两个玩家玩起来是好的":共享钱包/共用体力**是口径问题,不是 bug**(要改就得动 `stats` 的分身,影响面大)。
- `restart` 行中的进程内状态恢复仍是**缺口**，不能因为进程重新启动就认定状态已恢复。
